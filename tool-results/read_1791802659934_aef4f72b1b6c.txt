     1→# SaloonX — Salon Billing PWA — Project Worklog
     2→
     3→## Product Overview
     4→**SaloonX** is an ultra-simple salon billing PWA for Indian salons. Staff with zero computer experience must be able to bill in seconds. Admin gets full reports & management.
     5→
     6→## Core User Flows
     7→1. **Login**: POS-style — user taps their name tile → enters 4-digit PIN on a big numeric keypad. No typing usernames.
     8→2. **Billing (staff+admin)**: 3-step flow with big buttons:
     9→   - Step 1 Services: category chips + big service cards (name, ₹price, duration). Tap to add to cart. Floating cart bar with total.
    10→   - Step 2 Customer: big numeric keypad to enter 10-digit mobile (or "Skip — Walk-in"). On 10 digits, auto-lookup: returning customer → festive recommendation banner "Returning customer (N visits) — Apply X% off?" with Apply / Skip. Optional name for new customers.
    11→   - Step 3 Payment: bill summary + 3 big buttons: Cash (with quick-tendered chips & change calculator), UPI (shows QR — admin-uploaded image OR auto-generated from UPI ID with amount; plus "Payment Received ✓" button), Card (confirm on machine).
    12→   - Step 4 Success: animated check, receipt card, buttons: Share on WhatsApp (wa.me text receipt), More share (navigator.share), Download PDF, Print, New Bill.
    13→3. **Admin only**: Dashboard (today revenue/bills/avg, payment split, 7-day chart, top services), Transactions (filters, detail, CSV export, PDF export), Services CRUD, Staff CRUD, Customers list, Settings (salon profile, UPI ID + QR upload, GST toggle+%, loyalty rule: visits threshold + discount %, receipt footer).
    14→4. **Staff sees ONLY billing + logout** (no reports/transactions/settings).
    15→
    16→## Tech Decisions (sandbox-adapted)
    17→- Next.js 16 App Router, TypeScript, Tailwind 4 + shadcn/ui (New York), framer-motion, lucide-react.
    18→- **Single user-visible route: `/` only!** Entire app = client-side view switching (Zustand store `view` state). All other functionality via `/api/*` routes.
    19→- **Data**: Prisma + SQLite (this sandbox has no Firebase). Data access isolated in API routes so migration to Firebase (App Hosting + Firestore + Storage) later is contained. Custom session auth (PIN-based, node:crypto scrypt hashing, DB-backed session tokens in httpOnly cookies) — swap-able for Firebase Auth.
    20→- PWA: manifest.webmanifest + service worker + icons (already in `public/icons/`).
    21→- Currency: ₹ INR (Intl.NumberFormat en-IN). Bill numbers: `SX-0001`.
    22→- No blue/indigo. Theme: warm rose/deep rosewood primary, cream background, amber accents. Dark mode via next-themes.
    23→- Packages to add: `jspdf`, `jspdf-autotable`, `qrcode` (+`@types/qrcode`).

    77→## API surface (all JSON; errors are `{ "error": "message" }`; auth via httpOnly cookie)
    78→Auth:
    79→- GET /api/auth/users → `{ users: [{ id, name, role }] }` (active only, ADMIN sorted first) — no auth
    80→- POST /api/auth/login `{ userId, pin }` → `{ user: { id, name, role } }` + sets cookie; 401 "Wrong PIN"; pin must be 4 digits
    81→- POST /api/auth/logout → `{ ok: true }` + clears cookie
    82→- GET /api/auth/me → `{ user: { id, name, role } }` or 401
    83→Catalog (any authed):
    84→- GET /api/catalog → `{ categories: CategoryDTO[] }` — sorted by sortOrder then name; services sorted by name; INCLUDES inactive services (billing must filter `active === true`; admin services view uses the flag)
    85→- POST /api/catalog/category (ADMIN) `{ name, sortOrder? }` → `{ category: CategoryDTO }`
    86→- PUT /api/catalog/category (ADMIN) `{ id, name?, sortOrder? }` → `{ category }`; DELETE ?id= → 409 if it has services
    87→- POST /api/catalog/service (ADMIN) `{ name, price, durationMin?, categoryId }` → `{ service: ServiceDTO }`
    88→- PUT /api/catalog/service (ADMIN) `{ id, name?, price?, durationMin?, categoryId?, active? }` → `{ service }` (deactivate via active:false)
    89→- DELETE /api/catalog/service?id= (ADMIN) → 409 "Service is used in past bills — deactivate it instead"
    90→Customers:
    91→- GET /api/customers/lookup?mobile=10digits (any authed) → `{ customer: CustomerDTO | null, recommendation: { eligible, discountPct, visits } | null }` — recommendation is null when customer not found
    92→- GET /api/customers?search=&page=1&limit=50 (ADMIN) → `{ customers: CustomerDTO[], total }` — search matches mobile OR name, sorted lastVisitAt desc; CustomerDTO.lastVisitAt is ISO string | null
    93→Transactions:
    94→- POST /api/transactions (any authed) `{ items: [{ serviceId, qty }], customerMobile?, customerName?, discountPct?, paymentMethod, note? }` → `{ transaction: TransactionDTO, settings: SettingsDTO }` — prices computed server-side from CURRENT service prices; billNo SX-####; customer upserted (visits+1, totalSpend+total, lastVisitAt, name backfilled if null); all atomic in db.$transaction
    95→- GET /api/transactions?from=YYYY-MM-DD&to=YYYY-MM-DD&method=&staffId=&search=&page=1&limit=25 (ADMIN) → `{ data: TransactionDTO[] (with items), total, summary: { revenue, count, avgBill, byMethod: { CASH|UPI|CARD: { amount, count } } } }` — `to` inclusive, newest first, search matches billNo/customerMobile/customerName, default range last 30 days; summary covers the ENTIRE filter (not just page)
    96→- GET /api/transactions/[id] (ADMIN) → `{ transaction: TransactionDTO }`
    97→Stats:
    98→- GET /api/stats?from=&to= (ADMIN) → StatsResponse — default last 7 days incl. today; `daily` zero-fills dates (YYYY-MM-DD local, capped to most recent 90 days of range); `topServices` = top 6 by revenue (count = qty sold, revenue = price×qty); `newCustomers` = first-ever bills in range; `returningBills` = customer bills that are not their first-ever
    99→Staff (ADMIN):
   100→- GET /api/staff → `{ users: StaffDTO[] }` — StaffDTO = { id, name, role, active, billsToday, revenueToday }; never pinHash; ADMIN listed first
   101→- POST /api/staff `{ name, pin (exactly 4 digits), role }` → `{ user: StaffDTO }`
   102→- PUT /api/staff `{ id, name?, pin?, role?, active? }` → `{ user }` — 409 "Cannot demote or deactivate the last active admin"; deactivation deletes sessions
   103→- DELETE /api/staff?id= → 409 "Deactivate instead — this staff has past bills" if referenced; sessions cascade
   104→Settings:
   105→- GET /api/settings (any authed) → SettingsDTO (creates singleton default if missing)
   106→- PUT /api/settings (ADMIN) → SettingsDTO — upiQrImage must start with "data:image/" if present; gstPct/loyaltyDiscountPct 0–100
   107→Export:
   108→- GET /api/export/csv?from=&to=&method= (ADMIN) → text/csv; charset=utf-8 attachment saloonx-transactions.csv with BOM; columns: Bill No, Date, Time, Customer Mobile, Customer Name, Staff, Services ("Name x2; Name2 x1"), Subtotal, Discount %, Discount Amt, GST Amt, Total, Payment Method; default range last 30 days
